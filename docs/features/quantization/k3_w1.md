# Kimi-K3 1-bit experts

The `k3_w1` backend serves a converted Kimi-K3 checkpoint with sign-bit routed
experts, losslessly packed UE8M0 scales, int4/int8 dense weights, and an
`fp8_ds_mla` KV cache. It is intended for four NVIDIA GB10 systems using
TP=2 and PP=2.

## Model layout

The model repository must declare `"quant_method": "k3_w1"` in its
`quantization_config` and contain the converted expert stores:

```text
Kimi-K3-w1/
├── config.json
├── model-*.safetensors
├── tokenizer files
└── k3_w1/
    ├── pp0-tp0/experts.w2
    ├── pp0-tp1/experts.w2
    ├── pp1-tp0/experts.w2
    └── pp1-tp1/experts.w2
```

Each worker selects its store from its runtime pipeline and expert-parallel
ranks. The entire layout can therefore be downloaded on every node without
per-host environment variables.

Convert an official Kimi-K3 snapshot and create the complete model view with:

```bash
.venv/bin/python tools/k3_w1/convert_model.py \
  --model /models/Kimi-K3 \
  --output /models/Kimi-K3-w1
```

This is an offline conversion of every routed expert and requires about 426 GB
for the four output stores. If converted stores already exist, use
`tools/k3_w1/prepare_model.py` once per shard instead.

## Serving

Start a Ray cluster spanning the four nodes, then launch from the head:

```bash
vllm serve /models/Kimi-K3-w1 \
  --distributed-executor-backend ray \
  --tensor-parallel-size 2 \
  --pipeline-parallel-size 2 \
  --reasoning-parser kimi_k3 \
  --max-num-seqs 1 \
  --max-num-batched-tokens 512 \
  --max-model-len 1048576 \
  --enforce-eager
```

The model metadata activates `k3_w1`; the Kimi-K3 configuration enables
expert parallelism, round-robin expert ownership, and the `fp8_ds_mla` cache.
No external vLLM plugin is required.

The expert files are converted artifacts and cannot be reconstructed from the
ordinary MXFP4 checkpoint during server startup. A distributed model must
therefore publish all four `experts.w2` files with its dense checkpoint.
